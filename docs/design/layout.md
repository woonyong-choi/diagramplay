# 배치

## 단계

원본 → 글 재기 → 크기와 연결점 → ELK 그래프 또는 시퀀스 배치 → 선 라벨·제목 → 시간표와 글 상자 → 기하 검사 순서다. 측정한 도형 크기와 실제 카드 윤곽은 같다. ERD 컬럼과 API 필드는 잰 행의 높이에 선을 연결한다. 클래스 멤버는 연결점이 아니다.

## 자연 배치와 화면 맞춤

기본 그래프는 목표 폭을 강제하지 않는다. 방향·그룹·관계를 먼저 유지하고 읽기 쉬운 경로를 고른다. 선 길이·꺾임과 필요한 여백을 후보 비교에 반영한다. 화면 폭 680px를 이유로 자동 줄바꿈하지 않는다. 명시적 `aspect`와 내부 `layoutWidth` 요청만 배치 제약이 된다.

일반 HTML은 자연 배치 하나를 컨테이너 가로에 맞춰 축소한다. 가로 스크롤은 없고 세로 높이는 늘어날 수 있다. 전체화면에서는 확대·축소·이동을 허용한다. 화면 폭에 따라 다른 SVG·시간표를 교체하는 경로는 없다. 복잡한 그림은 축소되므로 전체화면으로 읽을 수 있다.

## 글과 카드

카드·본문·컬럼·멤버·라벨은 공통 글꼴로 먼저 측정한다. 글 좌우 여백을 포함해 너비를 정하고 긴 이름은 줄바꿈한다. `shape=tile`도 평소 카드 면·윤곽과 좌우 여백이 있다. 내용 변경에 필요한 가장 큰 크기를 배치 전에 확보한다. 그림별 좌표나 CSS 보정으로 넘침을 숨기지 않는다.

## 아이콘

NHN 공식 카탈로그를 공통 디자인 패키지에서 읽는다. 박스형 아이콘은 경계 제목 모서리에, 서비스·리소스는 독립 카드에 둔다. 원본 팔레트를 유지하며 일반 역할 아이콘을 자동으로 넣지 않는다. 등록한 사용자 SVG는 외부 참조·실행 코드·잘못된 크기를 검사한다.

그룹의 모서리는 공통 반지름으로 둥글게 하고 모서리에 붙은 아이콘도 같은 그룹 윤곽으로 자른다. 서비스 타일의 면과 텍스트 여백은 같은 카드 부품에서 정한다.

## NHN Cloud 가이드와 문서 검사

PPT 가이드의 경계 의미는 공통 카탈로그 `diagram.boundaries`가 소유한다. Region·Availability Zone·Auto Scaling Group은 점선이다. Cloud·Organization·Project·On Premise·VPC·Subnet·Security Group·Server Contents·Instance Contents·서비스는 실선이다. 알려진 그룹 아이콘은 의미를 자동 적용한다. `boundary=availability-zone`처럼 아이콘 없는 영역에도 지정할 수 있다. 아이콘 의미와 명시 의미가 충돌하면 오류다. 일반 그룹은 작성자의 `dashed` 선택을 유지한다. 선의 주 경로·보조 경로 구분은 경계 의미와 별개다.

### 선 그리기

- 경로는 elkjs의 직교 경로(`elk.edgeRouting: ORTHOGONAL`)다. 꺾이는 점의 모서리만 토큰 `radius.route`로 둥글게 한다.
- 경로 점은 옮기지 않는다. 한 가지 예외만 둔다. 그룹 경계 연결점의 높이는 그룹 안쪽 배치가, 선 끝은 바깥 배치가 정해서 몇 px 어긋나는 계단이 남는다. 연결점 제약이 없는 도형의 선 끝에서, 가로지르는 흔들림이 토큰 `spacing.2` 미만인 구간만 그 면 위에서 선 끝을 옮겨 편다. 옮긴 선 끝이 면 밖으로 나가거나 같은 면의 다른 선 끝(들어오는 선과 되돌아 나가는 선 포함)에 토큰 `spacing.1-25`보다 가까워지면 펴지 않는다. 펴서 선 끝이 붙으면 그림 검사 5번이 바르게 그린 선을 오류로 알리기 때문이다. 펴고 남은, 곧게 이어지는 가운데 점은 뺀다. 한 선분이 둘로 쪼개지면 검사 5번이 쪼개진 쪽을 도형에서 나가는 첫 선분으로 보지 못한다.
- 같은 자리의 점과 한 줄 위 가운데 점은 그릴 때 지운다. 그린 모양은 같다.
- 교차 마스킹은 둥근 모서리를 포함한 실제 경로를 편 선분에서 판정한다. 더 세로에 가까운 선을 끊고, 같은 기울기는 선언 순서로 결정한다. 도형 연결점 근처의 합류와 장면별 메시지는 끊지 않는다. 겹친 끊김 영역은 합쳐 evenodd에서 서로 지워지지 않게 한다(`draw/crossings.js`).

## 배치 실패

ELK가 실패하거나 경로를 만들지 못하면 안전 배치를 시도한다. 그래도 유효한 경로가 없으면 위치가 있는 `layout` 오류로 끝낸다. 겹침·도형 관통·연결점·제목 경계 검사를 통과하지 못한 출력을 숨기지 않는다.

## 명시적인 배치 목표 폭

`buildFigure(source, { layoutWidth })`는 양수인 유한수다. 그래프에만 적용하며 맞출 수 없으면 `layout-width` 경고를 낸다. `reflowFigure`는 내부 검사·재배치용으로 사건 시각을 유지하며 공개 API나 화면 자동 전환 기능이 아니다. 경로가 달라도 도착·대기 해제·값 변화 시각은 보존해야 한다.

## 그룹 헤더와 관계 라벨

아키텍처·카드 흐름·ERD·클래스의 그룹 제목은 같은 헤더 부품을 쓴다. 명시한 클라우드 영역 아이콘이 있으면 공식 아이콘을 쓰고, 일반 도메인 그룹에는 공통 카탈로그의 깃발 표식을 둔다. 자동 깃발은 제목 표식이며 Region 경계 의미를 추론하지 않는다. 일반 카드에는 아이콘을 자동으로 더하지 않는다.

관계 라벨은 번호 유무와 관계없이 배경을 채우고 외곽선은 두지 않는다. 번호가 있으면 원형 번호만 추가한다. `OK`·`WARN`·`FAIL`·`WAIT` 상태 배지도 같은 채운 면과 대비 글자 기준을 쓴다. 상태 의미에 따른 색만 구분한다. 배경·글자·활성 색은 공통 `color.figure.label-*` 토큰에서 정하며 밝은 테마와 어두운 테마를 함께 지원한다. HTML 재생과 움직이는 SVG도 같은 색과 상태를 사용한다.

설명·외래 키 삭제 정책은 경로 중앙에 가장 가까운 빈 자리부터 배치한다. 도형·선·제목·다른 라벨과 충돌하면 중앙에서 가까운 안전한 구간으로 옮긴다. 재생 글을 가리는 경우 확보한 통로를 우선한다. 다중성은 각 끝에 유지한다. 작성한 의미를 자동으로 삭제하지 않으며, 반복되거나 불필요한 설명은 작성 단계에서 생략한다.

다중성이 이웃 열의 관계선에 걸리면 끝 구간의 반대쪽과 첫 꺾임 주변에서 빈자리를 찾는다. 후보는 해당 경로 끝의 두 구간에 한정하고 도형·다른 라벨·선·이동 통로를 피한다.

시퀀스의 호출·응답 설명도 중앙을 우선한다. 중간 참여자의 생명선이나 메모를 가리지 않는 가까운 구간으로 옮기고, 자기 호출은 U턴 바깥의 라벨 자리를 쓴다. 생성·소멸로 선 끝이 바뀌면 최종 연결점으로 다시 중앙을 고른다.

구획과 일반 그룹은 같은 경계·제목 역할을 쓴다. 제목은 공통 그룹 글 크기·굵기로 재고 그리며, 분기 이름은 보조 글로 둔다. 생명선을 가리는 제목 밑면은 판과 같은 색이다. 카드의 내용 면과 영역 제목을 구분하고, 구획 제목에 버튼 같은 흰 면을 더하지 않는다.

연속 제어 구획은 경계를 맞붙이지 않고 공통 간격으로 나눈다. 글꼴 로딩 완료와 선택 상태의 전환이 끝난 실제 크기 화면으로 검사하며, 색 대비·겹침 검사 통과와 미적 완성도 판단을 구분한다.

단독 HTML의 그림·장면 탭·테마 선택은 같은 내장 글꼴을 쓴다. 테마 이름도 두 굵기의 부분 글꼴에 포함한다. 도표 원본이 영문만 담아도 조작부 한글이 시스템 대체 글꼴로 빠지지 않아야 한다.

HTML 판의 최대 폭은 선택한 표시 상한과 자연 그림 폭 중 작은 쪽이다. 좁은 그림의 판을 표시 상한까지 늘리지 않는다. 그림과 글자의 자연 크기는 유지하고 넓은 그림만 가용 폭에 맞춰 줄인다. 삽입과 단독 보기에서 같은 규칙을 쓰며 전체화면은 확대와 끌기를 유지한다.

비교 목록의 항목과 상세 블록은 공통 `color.gallery-surface`를 쓴다. 그림 자체의 작업 면은 `color.figure.canvas`다. 라이트의 흰 작업 면을 바꿀 때 목록 카드가 페이지와 같은 색으로 사라지지 않아야 한다. 두 테마의 목록·상세·재생 화면을 함께 대조한다.
