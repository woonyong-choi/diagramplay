# 문서 스킬 연동

문서 그림 스킬의 원본은 사용자의 skills 저장소 `docs/repo-docs-figures`다. 설치된 Codex 사본을 정본으로 취급하지 않는다. 스킬의 작성·검수 규칙과 DiagramPlay 구현·배포 상태는 별개로 확인한다.

## 그림 종류 대응

| 문서에서 보여 줄 것 | DiagramPlay 표현 |
|---|---|
| 요청과 처리 경로, 조건 분기 | 카드 흐름 |
| 서비스와 배포 경계 | 아키텍처 |
| 메시지 순서와 동시 호출 | 시퀀스 |
| 테이블·컬럼·키·관계 | ERD |
| 클래스·인터페이스·멤버·관계 | 클래스 다이어그램 |

API 필드, 카드 설명, 값·큐·상태 변화는 구성 요소로 유지한다. 통계 차트와 시계열 분석을 도구에 추가하지 않는다. ERD·클래스를 분석 차트와 혼동해 제거하지 않는다.

## NHN Cloud 구성도

스킬의 `references/nhn-cloud.md`는 PPT 가이드에 따른 영역·서비스·리소스·경로의 의미를 다룬다. 공통 디자인 카탈로그가 자산과 경계 기본값을 소유하고 렌더러가 적용한다. Region·Availability Zone·Auto Scaling Group은 점선, VPC·서비스 경계 등은 실선이다. 박스형 아이콘은 경계 모서리에, 서비스·리소스는 독립 타일에 놓는다. 장식 아이콘을 모든 카드에 붙이지 않는다. 공식 아이콘 팔레트를 유지하며 상태 색으로 덮지 않는다.

## 색 역할

화면의 색·글꼴·크기·여백·모서리·아이콘·조작은 `@woonyong-choi/design-tokens`에서 가져온다. 이 저장소는 값이나 CSS를 복사하지 않는다. 카드 면과 경계, 글자, 선, 현재 흐름, 상태는 서로 다른 의미 역할을 가진다. `tone`은 정의한 이름이고 `appearance`는 공통 변형이다. 이름 없는 점과 태그는 공통 카탈로그에 고정된 계열 순서를 반복한다. 색만으로 의미를 구별하지 않고 이름·연결·상태 글을 함께 쓴다.

## 조작과 선

HTML과 SVG는 같은 시간표·이동 곡선·상태 정의를 읽는다. 조작부는 공통 틀의 장면 탭·복사·다운로드·전체화면이며 전체화면에서 확대·이동한다. 일반 보기에서 가로 스크롤을 만들지 않는다. 선 교차 마스킹은 실제 둥근 경로와 같은 규칙을 사용한다.

## 변환과 검사

원본과 생성 SVG를 함께 관리하고 생성물은 손으로 수정하지 않는다. 원본 의미 검사, 기하 검사, 문서 품질 검사, 재생과 정지 출력, 설치 패키지를 확인한다. 실제 문서 폭과 라이트·다크에서 읽힘을 직접 본 범위와 자동 시험 결과를 구분한다. 대체 글은 그림의 결론을 말한다. 실측하지 않은 예제는 설명용 모형으로 표시한다.
